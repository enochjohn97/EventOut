Flow A — Attendee (web)

Discover & buy a ticket

Home / search→ Event preview→ Sign in→ Checkout→ Paystack→ QR ticket

A1 — Home & discovery

Public home page: hero with search, holiday alert, filter rail and the live event grid.

  1. Open https://eventout.com.ng/. The hero loads with the search bar and main navigation (Home, Events, About, Contact).
  2. Type an event name, organizer or category into Search events, organizers, categories and press Enter; results replace the grid.
  3. Use the Filter rail — Event Category, Location (State), Priority Tags, Status, Show only Free — and Reset to clear.
  4. Sort with Sort by: Newest First; the grid re-queries /api/events.
  5. Read a card: banner with category and Upcoming pill, date · time, name, venue, state, description, organizer with verified tick, price, heart and share.
  6. Tap the heart to save to favourites; tap share to copy the short link /e/<tag>.
  7. Click the card to open the event preview.

A2 — Event preview

Event preview: banner, name, organizer, date/time, venue, category, status pill, “About this event” and the ticket panel.

  1. The preview opens above the dimmed listing, or directly through /event-details.html?event=<tag> (short form /e/<tag>).
  2. Confirm the essentials: title, “Organized by …” with verified tick, date and start time, full address and state.
  3. Read Category and the status pill (Upcoming / Ongoing / Past).
  4. Scroll About this event for the description and attendee information.
  5. Continue to the ticket panel to choose a ticket type and quantity.

A3 — Checkout

Checkout: contact details on the left, event summary with quantity stepper and total on the right.

  1. Choose quantity and ticket type, then press Buy Ticket → /checkout.html?id=<eventId>&quantity=<n>&type=<ticketType>.
  2. Sign in if prompted; you return to the same checkout with the event intact.
  3. Enter Contact Information: first name, last name, email (receipts and tickets go here) and an 11-digit phone number.
  4. Check the Event Summary: banner, title, date/time, venue, ticket type and description.
  5. Adjust Quantity with the − / + stepper; Total updates live.
  6. Press Checkout ₦…. Free events issue the ticket immediately; paid events open Paystack.

A4 — Payment (Paystack)

  1. On the Paystack page choose card, bank transfer or USSD and complete the charge.
  2. Paystack returns to /r/<reference>, which resolves to the receipt page.
  3. Fulfilment is webhook-driven, so the ticket is issued even if the browser is closed early.
  4. While awaiting confirmation the page polls /api/payments/verify and shows processing; it switches to success once the webhook lands.
  5. On success you see the ticket reference, event summary and a link to the ticket.

A5 — Ticket delivery

  1. A ticket record is created with a signed QR payload that resolves through /t/<code>.
  2. The ticket is emailed (and texted when SMS is enabled) with the short link.
  3. Open /t/<code> to show the proof-of-purchase page with QR — this is what the organizer scans at the gate.
  4. Lost the email? The same ticket is listed in the organizer portal and in the mobile app’s Tickets tab.
StageWhat happens
InitializePOST /api/payments/initialize builds the reference, amount, organizer split and channels
WebhookMarks the payment paid, issues tickets, sends email/SMS
VerifyPOST /api/payments/verify — idempotent, returns success / processing / failed
ResendPOST /api/tickets/send re-sends the ticket email
Every ticket carries a unique code, so one scan admits one attendee. Duplicate scans are rejected at the gate.
Flow B — Organizer (client) portal

Organizer workspace

Login→ Dashboard→ Events→ Tickets + Scanner→ Payments→ Users→ Media

B1 — Log in

Organizer sign-in at /client/login.html.

  1. Open /client/login.html (short alias /clientLogin.html).
  2. Enter the organizer email and password; the eye icon reveals the password.
  3. Press Login →; the session is set and the portal shell loads.
  4. New organizer? Sign Up creates the account; it is reviewed before paid events go live.
  5. Forgotten password → Forgot Password? (B2).

B2 — Recover a password

  1. /client/forgot-password.html: enter the account email and submit.
  2. The server emails a one-time reset link when the address exists.
  3. Open the link → /client/reset-password.html: enter and confirm the new password.
  4. The token is consumed and you sign in again at B1.

B3 — Dashboard

Dashboard overview: Events, Tickets, Users and Media counters, event list, recent sales and performance trends.

  1. After login the portal opens /client/dashboard.html with the sidebar (Dashboard, Events, Tickets, Payments, Users, Media).
  2. Read the four counters: Events, Tickets, Users, Media.
  3. In Events switch between All Events and Past, then use + Create Event.
  4. Check Recent Sales for buyer, ticket type, channel and amount; View all opens Payments.
  5. Watch Performance Trends for revenue and tickets sold over the selected range.
  6. Use the bell for reminder notifications (T-30 and T-5 minutes before an event).

B4 — Create & publish an event

Events: created / published / scheduled / deleted counters, Active Events and Trash tabs, and the event table.

  1. Sidebar → Events (/client/events.html) → Create Event.
  2. Fill the identity: event name, category, description, tag (used in the public /e/<tag> URL) and contact phone.
  3. Set schedule and place: date, start time, state and address; add more locations for multi-venue events.
  4. Add ticket types and prices (regular, VIP, table), capacity and sales end time; price 0 makes it free.
  5. Upload banner and gallery media from the media library.
  6. Save as draft, schedule a publish time, or publish now; scheduled drafts auto-publish through the cron job.
  7. Review the row: event ID, name, date, category, ticket type, prices, capacity, sales, status and the public link.
  8. Deleted events move to Trash and can be restored.

B5 — Tickets & gate scanning

Tickets: sold, revenue, pending and cancelled counters, with the full ticket table and status badges.

  1. Sidebar → Tickets (/client/tickets.html).
  2. Confirm the counters: Tickets Sold, Total Revenue, Pending, Cancelled.
  3. Find a ticket by ID, event, buyer, price, ticket type, category, date or status.
  4. Open a row for attendee details, QR reference and check-in state; resend the ticket from there.
  5. At the gate open /client/scanner.html, allow camera access and scan the attendee QR.
  6. A valid unused ticket flips to checked in; a repeat scan reports “already used”; an unknown code reports “invalid ticket”.
  7. Use manual check-in for damaged codes.

B6 — Payments & payouts

Payments: totals, transaction list and filters by view, time period and status.

  1. Sidebar → Payments (/client/payment.html).
  2. Read Total Payments, Successful, Total Revenue and Failed.
  3. Switch View between Transactions and Refund Requests.
  4. Filter by time period (All Time, Today, 7 Days, 30 Days) and status (All, Paid, Pending, Failed, Refunded).
  5. Open a row for payer email, transaction ID, ticket count and settlement state.

B7 — Team accounts

Users: active, engaged and registered counters with the attendee/team table.

  1. Sidebar → Users (/client/users.html).
  2. Review the counters and the list: user ID, name, email, phone, state, source, status, country and city.
  3. Invite team members who may scan tickets or manage events; deactivate leavers.

B8 — Media library

Media: folder and file counters, folder list, and the Passed events archive shortcut.

  1. Sidebar → Media (/client/media.html).
  2. Use + New Folder to group assets (for example Event Assets).
  3. Open a folder to upload banners and galleries; reuse an asset across events.
  4. Switch the Active filter to review deleted or restored files; open Passed events archive for finished events.
Flow C — Admin portal

Platform administration

Login→ Dashboard→ Events→ Tickets→ Payments→ Clients

C1 — Log in

Admin sign-in at /admin/login.html — username and password.

  1. Open /admin/login.html (alias /adminLogin.html).
  2. Enter the admin username and password; press Login →.
  3. The admin session is set and the portal opens on /admin/dashboard.html.
  4. Admin and organizer sessions are separate — one never grants the other.

C2 — Dashboard

Platform overview: total events, active users, active clients, verification counts, revenue, analytics, activity and upcoming events.

  1. Read the KPI cards: Total Events, Active Users, Active Clients, Unverified, Verified, Revenue.
  2. Pick a range in Performance Analytics (for example Last 7 Days).
  3. Scan Recent Activities for the newest signups, events and payments.
  4. Use Active Users and Active Clients → Manage to jump to those pages.
  5. Browse Upcoming Events with the arrows and open an event directly.

C3 — Events

Events management: platform-wide event table with status, tag, public link and filters.

  1. Sidebar → Events (/admin/events.html).
  2. Review counters: Events Created, Published, Deleted, Scheduled, Restored.
  3. Filter by status, category, price and attendees.
  4. Inspect a row: event ID, name, organizer, date, time, category, phone, price, attendees, tag, link and status.
  5. Open the public page from the link icon, or manage the event from its row.

C4 — Archive

Archive: every event that has already taken place, with its own search.

  1. Sidebar → Archive.
  2. Search archived events by name or tag.
  3. Open an archived event to review its tickets, sales and media.

C5 — Tickets

Tickets management: issued, revenue, pending, scanned and cancelled, with every ticket on the platform.

  1. Sidebar → Tickets (/admin/tickets.html).
  2. Read Total Issued, Total Revenue, Pending, Scanned and Cancelled.
  3. Search by ticket ID, event, buyer, price, category, date or status badge (Valid / Pending).
  4. Open a ticket to resend it, verify payment, or check in the attendee manually.

C6 — Payments

Payments management: platform totals, transaction and refund views, filters and the full ledger.

  1. Sidebar → Payments (/admin/payments.html).
  2. Read Total Payments, Successful, Total Revenue and Failed.
  3. Switch View to Refund Requests to action refunds.
  4. Filter by time period and status (Paid, Pending, Failed, Refunded).
  5. Reconcile a row with its transaction ID, organizer, amount, ticket count, user email and status.

C7 — Clients

Clients management: registered, active and event-creating organizers with their profile records.

  1. Sidebar → Clients (/admin/clients.html).
  2. Read Clients Registered, Clients Active and Clients Created Events.
  3. Review the table: client ID, name, email, date of birth, gender, address, city, country, state, job title and account number.
  4. Open a client to approve, suspend or inspect their events and payouts.
Approval here unlocks paid publishing for that organizer; suspension hides their live events from the attendee site.
Flow D — Mobile attendee app (Flutter)

EventOut mobile

Splash→ Onboarding→ Google sign-in→ Profile→ Home shell

Signed-in tabs: Home · Favorites · Tickets · Profile. The app talks to the same API as the website.

D1 — Launch, splash and onboarding

  1. Splash shows the brand while the app resolves the API origin, restores the stored session and warms the cached feed.
  2. First launch shows Onboarding slides with Skip and Continue; the flag is stored so it never repeats.
  3. No stored session → the app opens the sign-in screen instead of the feed.
  4. Valid stored session → straight to Home, with the cached first page rendered instantly and refreshed in the background.

D2 — Sign in with Google

  1. Press Continue with Google (Android Credential Manager, iOS Google Sign-In SDK).
  2. Pick the Google account; the SDK returns an ID token.
  3. The app posts it to POST /api/auth/google and receives a session token.
  4. The token is stored securely and sent as Authorization: Bearer … on every request.
  5. New accounts complete Profile: name, phone (11 digits), gender → Save → PUT /api/profile → Home.

D3 — Home feed

  1. The feed lists published events with banner, name, date, venue and price; pull down to refresh.
  2. Search and sort re-query GET /api/events; each combination caches its first page for instant offline launch.
  3. Tap a card for the event detail sheet; tap the heart to save it to Favorites.
  4. Tap an event published push notification to deep-link into that event, cold start included.

D4 — Event details and checkout

  1. The sheet shows banner, organizer, description, venue with map, date/time, ticket types and remaining capacity.
  2. Get Ticket opens /checkout; Get for someone else opens it in gift mode (recipient email only).
  3. Confirm quantity and ticket type; the profile email and phone are pre-filled and the total shows ticket plus fees.
  4. Press Pay → POST /api/payments/initialize, which builds the Paystack transaction with the organizer split.

D5 — Payment and success

  1. The Paystack page opens in an in-app WebView — card, transfer or USSD.
  2. After the charge the WebView closes and the app polls POST /api/payments/verify for about 15 seconds.
  3. Success opens the success screen with the ticket reference and a shortcut to Tickets.
  4. Processing is not a failure: the ticket appears in Tickets as soon as the webhook lands.

D6 — Tickets

  1. The Tickets tab lists your tickets with event, type, date and check-in state.
  2. Tap a ticket for the full QR to show at the gate.
  3. Lists are cached per account, so tickets open without a connection.
  4. Resend a ticket by email from the ticket actions.

D7 — Favorites

  1. The Favorites tab shows the events you hearted.
  2. Toggling a heart calls POST /api/favorites/toggle; removing it drops the row.
  3. The list is cached per account and visible offline.

D8 — Profile

  1. Profile shows name, email and phone; Edit Profile applies the same validation as web.
  2. Terms, Privacy, Cookies and Delete your data open in-app.
  3. Log Out clears the token, cached favourites and cached tickets for that account, then returns to sign-in.

C. Reminder jobs

Pages ping /api/cron/run-reminders.php, which self-throttles to one run every two minutes and fans out to cron/notify-pre-event.php: T-30 minutes (admin and organizer in-app, attendee email/SMS), T-5 minutes (admin and organizer), plus auto-publishing of scheduled drafts.
